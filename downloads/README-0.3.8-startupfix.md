# Windows 0.3.8-startupfix · 시작 감지와 현재 오류 안내 보완

[EXE 포함 ZIP 다운로드](Bbolprom-Windows-x64-v0.3.8-startupfix.zip)

ZIP **전체를 새 폴더에 압축 해제**하고 Bbolprom.exe를 실행하세요. EXE/app/runtime을 함께 유지합니다. 기존 자료 폴더는 삭제하지 않습니다. 이미 사용 중인 휴대형 data가 있다면 data를 함께 옮기거나 같은 폴더의 프로그램 파일만 교체하며 data를 보존합니다.

1. 다른 자료 폴더의 뽈프롬이 예전 포트를 사용하는 경우를 구분해 잘못된 실행 중 차단을 줄였습니다.
2. **이전 앱 화면이 따로 열리면 그 화면의 [앱 종료]를 누르세요.** 그다음 새 버전의 Bbolprom.exe를 다시 실행합니다. 기존 브라우저/프로세스를 찾아 강제 종료하는 절차를 요구하지 않습니다.
3. 오류가 계속되면 오류창의 **현재 이유·주소**와 이번 실행 시각/버전이 적힌 startup-error.log를 확인하세요. 이전 오류 로그는 다음 시작 전에 정리합니다.
4. 정상 화면이 열리면 **PT.hwpx 원본 보관** 버튼에서 파일을 선택합니다. PT를 프로그램 폴더에 직접 넣을 필요는 없습니다.

최초309개 정답·이미지 매핑·태그/하이라이팅·사용자 수동 수정 이력은 유지합니다. 앱을 강제 종료하거나 runtime.json/data를 삭제하지 않으며 실제로 같은 자료를 쓰는 앱의 복사는 계속 차단합니다. 키는 Windows 보관함, 자료는 프로그램 옆 data 정책을 유지합니다.

사용자 로그에는 기존 health 응답으로 차단된 사실이 나옵니다. 개발 환경에서 다른 자료 폴더 앱의 포트 재사용 오인 차단을 재현했지만, **사용자PC의 정확한 응답 프로세스나 같은 원인 여부는 아직 확정하지 못했습니다.**

통합188개(새9개 중 Windows 프로세스 API 모형3개 포함), 실제 Chromium의 원본보관/수정/폴더이동 회귀8개 통과. 교차빌드1350개 파일 해시·ZIP CRC·Linux 패키지 소스/원본복원·이동 확인. 실제 Windows 팝업/프로세스 API·실제605MB PT·실API·사용자PC 재시도 성공은 미검증입니다. 사용자DB·실제키·유료API는 사용하지 않았습니다.
