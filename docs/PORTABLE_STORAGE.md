# 휴대형 자료 폴더 — 0.3.7-portable

최초309개 정답·이미지 매핑은 그대로 두고 자료 위치를 프로그램 옆 data로 모았다. 사용자 수동 태그 수정과 원본/이전 버전 복원 정책을 유지한다. 실제 API 호출·모델 재학습·신규HWPX 자동분할을 추가한 변경이 아니다.

## 첫 실행과 기존 사용자

ZIP 전체를 쓰기 가능한 폴더에 풀고, 이전 앱에서 **앱 종료** 후 Bbolprom.exe를 실행한다. 런처는 EXE 위치를 --portable-root로 전달한다. 프로그램 폴더의 data를 기본으로 사용하며 현재 작업 폴더나 이전 문서의 절대경로에 의존하지 않는다. 쓰기 불가 위치에서 알리지 않고 다른 폴더로 우회 저장하지 않는다.

처음 사용하는 경우 PT.hwpx 선택 → 이미지 연결 검토 → 등록을 진행한다. 원본은 data/sources/PT.hwpx에 바이트 그대로 보관하고 이미 확정한309개 ID와531개 순서 참조/522개 경로로 원본 이미지를 연결한다. 기존 태그·분류·하이라이팅을 재생성하지 않는다. 원본 파일 SHA를 먼저 검사하므로 다른 문서는 기존 자료를 유지하고 거절한다.

0.3.6 이전 사용자의 기본 %LOCALAPPDATA%/Bbolprom 자료가 있으면 새 data가 비어 있을 때 복사·검증해 전환한다. 기존 폴더는 삭제하거나 수정하지 않는다. 카드/수정 이력/이미지/설정/일일 호출 예약 DB와 저장된 백업·내보내기까지 복사한다. 실행 중인 이전 앱이 발견되면 앱 종료 후 재시도를 안내한다. 큰 복사 작업에는 준비·복사·검증 진행 화면을 표시한다.

이전 버전은 PT 전체를 보관하지 않았으므로, 카드·이미지·수정 이력은 유지한 상태로 **PT.hwpx 원본 보관**을 한 번 선택한다. 이 동작은 원본 전체 복사만 수행하고309개를 재등록·재분석하지 않는다. 새 사용자 등록 완료 시에는 별도 선택 없이 PT 원본을 함께 보관한다.

## 배치

```text
뽈프롬/
  Bbolprom.exe
  app/                         프로그램
  runtime/                     번들 Python
  data/
    library.sqlite3            고정309·사용자 수정 이력·신규카드·연결·설정
    api-safety.sqlite3         일일 호출/예상 비용 예약
    portable.json             자료 배치와 이사 검증 기록
    sources/PT.hwpx            베이스파일 전체 원본
    vault/<sha256>             검증한 원본 이미지 바이트
    new_cards/<card-id>/
      원문-<sha256>.txt          원문 버전별 UTF-8 원본
      originals/<sha>-원래이름  원본 이미지, 확장자 유지
    backup/                    백업
    exports/                   사용자 내보내기·진단
```

신규 카드마다 ID별 폴더를 만들고 원문과 원본이미지를 복사한다. 원문 변경 시 이전 버전 파일과 수정 이력도 보존한다. 이전 카드 버전의 원문/이미지도 자료 이사 시 보관한다. 파일명이 충돌하지 않도록 해시를 붙이고 Windows에서 사용할 수 없는 문자·긴 이름은 보관명만 안전하게 정리한다. 원래 이름은 DB 출처에 보존한다. 원본 데이터는 리사이즈/재인코딩하지 않는다.

화면은 검증된 vault 원본을 읽고 신규 카드 폴더에도 열어볼 수 있는 원본을 보관한다. 자료 폴더 열기와 신규 카드 원본 폴더 버튼을 제공한다. 이 버튼은 고정된 자료 경로/존재하는 카드ID만 열고 임의 경로를 받지 않는다. 현재 등록 원문·태그의 정본은 DB다. 폴더의 원문 파일을 외부에서 수정해 DB/태그를 자동 변경하는 기능은 없다. 파일을 확인할 수 있으며 변경은 앱에서 한다.

## 새 Windows PC와 프로그램 업데이트

앱 종료 후 **뽈프롬 폴더 전체**를 복사한다. 특히 data를 함께 가져와야 사용자 태그 수정 이력과 신규 카드가 유지된다. PT만 가져오는 것은 사용자 수정 DB를 이사하는 동작이 아니다. 이미지·문서·원본의 연결은 data 기준 상대경로여서 드라이브/사용자명이 바뀌어도 유지된다. API키는 Windows 보관함에 있으므로 새PC에서 다시 등록한다. 일일 사용 원장은 data와 함께 옮겨져 폴더 이동으로 초기화하지 않는다. 두PC 동시 편집·동기화는 이번 범위가 아니다.

업데이트는 data를 유지하고 프로그램 파일만 교체한다. 새 프로그램 폴더로 옮긴다면 data도 함께 가져온다. 빈 새 폴더에서 실행하는 업데이트를 위해 현재 PC의 %LOCALAPPDATA%/Bbolprom-portable-location.json에 마지막 정상 data 위치만 기록한다. 사용자 카드/이미지/키는 이 위치 기록에 들어가지 않는다. 알려진 최신 휴대형 자료가 있으면 오래된 LocalAppData 자료보다 우선 복사한다. 기록된 자료가 없으면 조용히 옛 라이브러리로 돌아가지 않고 기존 data를 가져오도록 안내한다. 이미 data가 들어 있는 폴더는 다른PC의 위치 기록과 무관하게 그 자료를 사용한다. 이 위치 기록은 폴더 전체 이동에 필수인 파일이 아니다.

## 복사·원본·실패 보호

이사는 임시 형제 폴더에 SQLite 스냅샷과 파일을 복사하고, DB 내용/원본309/수동 수정 이력/모든 연결 파일의 해시를 검증한 뒤 data로 전환한다. 복사 중 원본 DB/파일이 바뀌거나 공간 부족·복사 오류·손상이 있으면 전환하지 않는다. 기존 라이브러리를 덮어쓰거나 삭제하지 않는다. 외부로 이어지는 파일 링크와 저장소 밖으로 나가는 경로를 거절한다.

이후 실행은 자료 존재/크기와 기준/이력 무결성을 확인한다. 매 실행마다 모든 대용량 파일의 해시를 전부 읽는 방식은 아니다. **진단 로그 내보내기**에서는 원본 문서·신규 원본 파일까지 해시를 다시 읽어 검사한다. 진단에는 개수/해시/오류만 포함하고 원문·이미지·원본 파일명·API키·절대경로는 포함하지 않는다.

전체 **백업 저장**에는 DB·vault·카드별 원본·PT 원본을 포함한다. 작은 수정 전의 자동 백업에는 큰 PT를 매번 중복 압축하지 않는다. API 사용 원장은 과거 백업 복원으로 초기화하지 않도록 백업 ZIP에서는 제외하고 폴더 전체 이동에는 포함한다. 새PC의 전체 백업 가져오기 UI는 이번에 추가하지 않았으며, 현재 권장 이사 방법은 전체 폴더 복사다.

프로그램 ZIP에는 사용자 data/DB/원본PT/이미지/키를 포함하지 않는다. PT606MB와 검증 이미지954MB를 함께 보관하면 베이스자료만 약1.56GB이며, 신규 원본과 백업 용량은 별도다.

검증은 평가 로그와 배포 README에 기록한다. 합성 파일·임시 DB·로컬 브라우저·Linux 프로세스로 수행하며, 실제 Windows의 새 런처/자료 이사와 실제605MB 베이스파일 실행은 별도 사용자 확인이 필요하다.
