# Windows 등록 저장 오류 수정 — 0.3.5-windowsfix

사용자가 제공한 0.3.3 Windows 진단에서 베이스파일 SHA256 일치, 309개 기준 카드와 522개 원본 이미지 경로의 검토 완료를 확인했다. 등록 요청은 서버에 도달했으며 `commit_failed / PermissionError / errno 13`이 기록됐다. 저장된 연결은 0/531, 등록 출처는 0건이다. 원래 진단에는 전체 경로·스택·Win32 오류 번호가 없어 해당 로그만으로 실패한 코드 줄을 확정할 수는 없다. 원본 진단 ZIP과 세부 사용자 기록은 저장소에 공개하지 않았다.

## 재현한 결함과 수정

`sqlite3.Connection`의 `with`는 커밋/롤백을 수행하지만 연결을 닫지 않는다. 기존 백업은 대상 임시 DB 연결을 계속 보유한 채 `finally`에서 임시 파일을 삭제했다. Windows는 열린 DB 파일의 삭제를 거절할 수 있어, 백업이 등록 전에 실패하는 경로가 있다. Linux에서는 열린 파일 삭제가 가능해 기존 시험으로 발견하지 못했다.

`tests/test_windows_storage.py`는 연결을 강제로 보유하고 열린 DB 삭제 시 `PermissionError(13)`을 발생시키는 Windows 잠금 모형으로 이 경로를 재현한다. 수정 전 3개 시험은 실패했고, 수정 후 모두 통과했다. 이 시험은 실제 Windows 실행이 아니다.

- `ClosingConnection`은 기존 트랜잭션 커밋/롤백을 수행한 뒤 성공·실패 모두 연결을 닫는다. 라이브러리·백업 대상 DB·API 사용 원장에 적용한다. 백업 내용을 바꾸거나 기존 데이터를 지우지 않는다.
- 등록 검토창 내부에 진행 상태와 오류를 표시한다. 처리 중 중복 등록·취소를 막고, 실패 후 진단 내보내기·동일 세션 재시도를 허용한다. 페이지 아래 가려진 오류만으로 무반응처럼 보이던 부분을 보완한다.
- 진단 오류에 가능한 경우 Win32 숫자와 허용된 백업 작업 단계만 기록한다. 전체 경로·임의 오류 메시지·키를 추가하지 않는다.
- 동봉 Windows 시험 스크립트에 실제 임시 백업 생성과 삭제 확인을 추가했다. 개발 환경에서 Windows로 실행한 결과는 아직 없다.

고정309카드·531개 순서 참조·원본 마스터·API 태그 판단 정책·하이라이팅 판단 방식은 변경하지 않았다. 후속 엔진 개선은 사용자 베이스파일 재시험과 매핑 확정 전까지 보류한다.

## 검증과 재시험

통합140개(새 잠금 모형3개·안전한 오류 메타데이터1개 포함), 실제 로컬 브라우저6개 시나리오를 통과했다. 브라우저는 합성 파일과 한 차례 저장 오류 주입을 사용해 진행 표시 → 실패 안내 → 진단 기록 → 동일 세션 재시도 → 531개 연결/522개 경로의 저장 해시 검사를 수행한다. 실제 API·실제 키를 사용하지 않았다.

0.3.5를 새 폴더에 풀고 이전 앱에서 **앱 종료** 후 실행한다. 기존 데이터 폴더를 그대로 사용한다. 베이스파일을 선택 → 검토 → 등록 → 진단 로그 내보내기로 재시험한다. 실제 사용자 Windows에서 수정 효과가 확인됐다고 보고하려면 새 진단의 저장 연결531건과 무결성 결과를 확인해야 한다. 기존 제공 로그의 Windows 원본 읽기 성공과 수정 버전의 Windows 저장 성공을 구분한다.
