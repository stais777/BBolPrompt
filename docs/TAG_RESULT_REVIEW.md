# 저장된 태그 결과 검수 — 0.4.3-review

API 결과에는 판단·미분류 사유가 저장돼 있지만, 기존 태그 버튼과 수정/이력 화면에서는 사유를 읽기 어려웠다. 미분류 후보의 원문 근거와 기존 표준의 존재를 확인할 수 있도록 표시를 보완했다.

신규 카드의 태그를 누르면 기존 원문 하이라이팅과 함께 다음을 표시한다.

- 저장된 판단/미분류 사유. 사유가 없는 이전 수동 데이터에는 없는 사실을 그대로 표시한다.
- 현재 원문에서 코드포인트·문자열이 일치하는 근거 구간. 확정 구간이 없으면 경고하며, API가 제시했던 후보 구절은 위치 확정 전으로 따로 표시한다.
- 같은 이름의 현재 기준 태그 분류와 기준 카드 수. 원본 카탈로그 대신 화면에 적용된 최신 사용자 수동 태그 수정본을 읽는다. 같은 이름의 표준이 있어도 신규 원문의 문맥·근거가 자동 승인되는 것은 아니다.
- 기존 태그 수정 화면을 여는 버튼. 버튼을 누른 것만으로 저장하거나 분류를 변경하지 않는다.

`partial`에는 ‘분석 완료·미분류 후보 있음’이라는 설명을 추가했다. 기준 카드에서는 새 검수 패널을 표시하지 않으며 기존 강조·수동 수정 동작을 유지한다. 상세 보기에도 같은 읽기 전용 검수 표시를 제공한다.

## 변경하지 않은 처리

API 요청/응답 계약·관련 사례 선택·모델·분류 정의·정규화·원문 근거 판정·수동 보호·키 보관·비용/호출 한도·DB/이미지 저장은 그대로다. 최초309개를 재분석하거나 기존 결과를 자동 재분류하지 않는다. 파일에 없는 과거 사유를 새로 만들지 않는다. 검수 화면은 추가 API 호출 없이 이미 저장된 결과를 읽는다.

- 로컬 HTTP17개: `evaluation/tag-review-http-tests.log`.
- 새 Chromium6개: `scripts/tag_review_browser_smoke.js`, `evaluation/tag-review-browser.json`. 실제 임시DB에 저장한 모의 partial 결과, 사유/구절/표준 후보, 자동 분류·저장 없음, 텍스트 안전 출력과 키 마스킹, 상세 보기/수정창/새로고침/기준 보존을 검증했다.
- 기존 Chromium48개: API8·작업응답9·갤러리16·베이스수동태그9·보안6. `evaluation/tag-review-*-browser.log`.
