# 승인 기록 대조와 태그·하이라이팅 방법론 분석

분석일: 2026-11-05 (한국 시간). 이번 범위는 **인계된 판단·승인 과정을 대조하고 API 요청에 연결하는 것**이다. 로컬 HWPX 분리 개선·새 베이스화 등록 경로·UI 개편·새 Windows 배포는 이번 작업에서 진행하지 않았다.

## 작업의 기준

- **베이스화:** 사용자가 검증을 마친 마스터 엑셀의 확정309카드를 고정 데이터로 정확하게 등록하는 일이다. 독립 엔진의 추출 성공을 뜻하지 않는다.
- **엔진의 방법:** 원문 정독, 의미·부정·상태·주체 판단, 세로/가로 정규화, 정정·통합·삭제·분화·유지·이동 판단, 실제 근거 매핑 및 검증의 과정이다.
- **API 역할:** 이 방법과 관련 승인 사례를 참고해 신규 카드의 태그·분류·근거를 제안한다. 모델 자체를 재훈련했다고 주장하지 않는다. 원문·이미지·베이스화 자료를 직접 변경할 권한을 주지 않는다.

중복·차수별 과거 기록을 포함한 **레코드 수**이지, 새 규칙6,416개나 독립 판단6,416개를 뜻하지 않는다.

`final_confirmed`는 **최종 매핑의 존재·분류와의 일치**를 뜻한다. 사유 전체에 대한 새 의미적 승인이나 모델 정확도 인증이 아니다. 출처의 원래 필드는 바꾸지 않았다. 실제 출처19개 및 원본 행/JSON 포인터6,416개를 대조해 복사 필드 차이0건을 확인했다.

## 실제로 구분한 문제

1. **오래된 미승인 표기9건:**14차216~235 배열에는 개별 `미승인 / 마스터 변경 없음`이 남아 있다. 뒤의 전건 승인 인계문서와 건수9개, 최종 마스터 값이 일치한다. 원래 문구는 유지하고 승인 증빙을 별도로 연결했다.
2. **열 글자의 시점 차이:**과거B/C/F/G/H는 현재C/D/G/H/I에 해당한다. 원문 헤더는 보존하고 현재 분류를 별도 필드로 기록했다. 가로 정규화 문서는 이미 현재C~I를 사용한다.
3. **중복 기준ID:**예를 들어 `2차-N01`이 분류 이동과 유사어 정리에 각각 등장한다. ID문자열 하나로 합치지 않고 원본 시트·행을 구분하는 고유 기록ID를 사용한다.
4. **초기 정정 사유 없음:**삭제나 통합만 기록되고 사유가 없는 항목도 있다. 없는 사유나 실제 대화 문장을 새로 만들지 않았다.
5. **최종 유지와 빈 하이라이팅:**17개 빈span은 역사적으로 유지 승인한 예외다. 태그를 삭제하지 않으며, 모든 신규 태그를 무근거로 자동 확정할 수 있다는 일반 규칙으로 만들지 않는다.

## 새 방법론 문서에서 확인한 과정

API에 제공할 보조 방법론은 원문46개 절로 구성했다. 모두 원본 문장과 행 번호·SHA를 보존한다.

- 의미 판단축10개:사실성, 부정, 시간·실제 수행/준비/암시, 주체, 자세, 의상/직업, 장소/소품, 동의어, 분류 충돌, 원문 보존 등.
- 처리 순서7개:원문 분석→상태 구분→특징·분류→정규화→불확실 후보 분리→근거 검증→반영.
- 세로7단계·가로6단계:분류 내부와 분류 간 정규화를 구분하고, 독립 개념의 분화 및 K합집합 검증까지 보존.
- 하이라이팅 불변14개:코드포인트·원문SHA·문자열 대조, 다중 근거, 승인 전 임시 근거와 최종 근거 구분, 빈span 예외 등.
- 역사적 예외2개:같은 원문의 과거 카드ID 유지 및 초기 외형 태그 제외 원칙을 최종 승인 외형 태그 삭제에 일반화하지 않는 기준.

자료의 설명은 **기존 작업을 재구성한 방법론**으로 표시한다. 최종 승인 원본과 같은 권위의 새 제품 정책으로 올리지 않는다. 입력HWPX를309개로 고정하는 규칙이나 단어별 자동 태그표로 바꾸지 않았다.

## 충돌/한계와 우선순위

- 새 문서에는 v0.3.1 추출665개라는 기록이 있으나 사용자가 제공한 화면은495개다. 같은 실행인지 확인되지 않아 두 값을 섞거나 사용자 실측을 덮어쓰지 않았다.
- `01_full_process.md` 일부 중간 집계는1297/2573을 과거E/장소 및F/상황으로 설명한다. 실제 시트는 `F_001-309_승인원본1297`의 상황·관계 표현, `G열_승인반영_요약`의 자세·구도 기록과 연결된다. 요약의 열/수량 명칭만 따라 현재 분류를 바꾸지 않는다.
- `02_decision_rules_examples.md`의304번 설명은 `자연스러운 C컬 단발→C컬 단발` 정리를 말하지만, 같은 패키지의 최종 데이터에는 I열 `자연스러운 C컬 단발`이 남아 있다. 요약 설명을 최종 승인 치환 규칙으로 올리지 않고 현재 값을 보존했다.
- 첨부의 독립 로컬 엔진 목표는 현재 사용자의 **로컬 분리 중단·베이스화 우선** 지시를 대체하지 않는다.
- 하이라이팅 문서의 API 위치후보 설명은 현재의 **API근거구절 반환→프로그램이CP좌표 계산·검증** 계약을 바꾸지 않는다.
- 일부 초기 대화의 문장별 로그는 제공 자료에 없다고 패키지 자체도 명시한다. 기록되지 않은 정반합 대화를 복원했다고 주장하지 않는다.

우선순위는 **현재 명시적 사용자 지시/API확정 정책 → 최종 마스터·실제 승인내역 → 재구성된 방법론 설명**이다.

## 실제 코드 연결과 검증

- `approval_history.py`:관련 이력 선택, 최종 불일치/보류 제외, 후행 판단 동반, 출처 보존.
- `method_guidance.py`:의미 판단·세로/가로 정규화·근거 매핑 방법론의 스키마/크기/출처 검사.
- `api.py`:8단계 승인 절차·19정책, 관련 승인 기록, 방법론46절과 선택된 베이스화 사례를 한 요청으로 전달한다. 예전4시트285행을 함께 중복 전송하지 않는다.
- `library.py`:실제로 요청에 제공한 기준ID·원본 출처·데이터SHA를 저장한다. 이는 모델이 모든 기준을 정확히 적용했다는 인증이 아니다. API실패 때에도 기존 태그와 원문은 유지하고 참조 출처만 남긴다.

증빙은 `evaluation/approval-history-*`, `evaluation/method-handoff-analysis.json` 및 통합시험 로그에 있다. 테스트는 모의 공급자를 사용한 계약/근거/출처/저장 검증이며 **실제 API 의미 정확도 시험이 아니다**. 현재 새 소스는 아직 기존 Windows ZIP에 반영하지 않았다. UI인계 ZIP은 별도 보관만 했으며 분석하지 않았다.

## 아직 연결·검증이 끝나지 않은 부분

실제 API 의미 정확도는 호출하지 않아 검증하지 못했다. 참고 이력 선택은 어휘 기반 검색이며 관련 사례를 의미적으로 항상 올바르게 찾는다고 보장하지 않는다. 반복되는 동일 근거의 문맥별 위치 선택 보조 함수는 있지만, API응답의 별도 선택자 필드로 완전히 연결하지 않은 상태다. 현재는 충분한 인용과 모호성 경고를 사용하며 이 한계를 해결했다고 보고하지 않는다. 기존 초기 분류는 표시명만 있어, 실제 API작동에 필요한 활성 분류 정의·공급자·모델·키 설정도 이번 자료 대조 작업에서 임의로 새로 확정하지 않았다.

추가로 받은 베이스화 최종검수 ZIP과 별도 마스터도 확인했다. 두 번째 마스터는 기존 확정 SHA와 같고, 첫 ZIP의309카드·531참조·과거522경로와 같은ID로 연결된다. 상세 범위와 원본PT미동봉 한계는 `BASELINE_INPUT_LINKAGE.md`와 `evaluation/baseline-handoff-analysis.json`에 구분했다.

이번 소스의 통합시험은96/96통과했다(`evaluation/approval-history-integrated-tests.log`). 모의 API 계약/전달/출처/저장 시험이며 의미 정확도 시험이 아니다. 기존 Windows 배포 ZIP은 갱신하지 않았다.
