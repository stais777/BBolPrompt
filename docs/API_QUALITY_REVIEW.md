# 신규 카드 API 보완 — 0.4.4-quality

기존 태그와 정확한 원문 근거를 보존하면서 신규 카드의 판단·검수 정보를 보완한다. 현재 단계는 사전준비이며 영상 엔진·영상 UI는 구현하지 않는다.

- 현재 참고 순위에서 누락되던 큰 눈·하체 근육 발달·하얀 패디큐어는 해당 긍정 묘사가 있을 때 먼저 참고 목록에 전달한다. 이는 자동 태깅 규칙이 아니다.
- 기존 표준을 명시적으로 선택한 응답은 ID·이름·현재 분류를 함께 사용한다. 유효한 긍정 근거, 명시적인 기존 ID 선택, 단일 표준 이름, 활성 분류가 모두 확인될 때만 분류 튜플을 정합하게 보정한다. 잘못된 ID·다른 이름·거짓 근거·명시적 미분류는 자동 승인하지 않는다.
- 승인된 패디큐어 동의어는 색상과 정확한 근거가 확인될 때 기존 E 표준으로 통일한다. 사용자 수동 태그와 제외 선택은 동의어 보정 이후에도 우선한다.
- 줄 시작의 `negative:` / `negative prompt:` / `부정 프롬프트:`부터 다음 명시적 `positive:` / `긍정 프롬프트:` / `추가 긍정 설명:` 또는 원문 끝까지 태그 대상에서 제외한다. 일반 본문의 부정은 계속 해석한다. 경계를 가로지르는 근거는 검토 대상으로 보존한다. 원문은 수정하지 않는다.
- 과거·현재, 준비·명령·암시·실제 수행, 주체·대상, 접촉·압박·삽입과 상충 문맥의 검토 지침을 강화한다. 의미 판단은 모델 응답과 실제 결과 검수가 필요하다. 별도 수행 상태 필드는 만들지 않는다.
- 선택적인 사용자 검수 중점은 API 설정에 보관하며 요청에 함께 제공한다. 이는 누락 점검용이며 원문에 없는 특징을 추가할 근거가 아니다. 내용은 진단·최근 호출 상태에 포함하지 않으며 실행 감사에는 해시만 남긴다. 변경 중점으로 진행 중 결과가 낡으면 적용하지 않는다.
- 태그별 API 원래 제안과 이유를 보정 전에 확보한다. 저장된 이유·제안 분류·기존 표준·보정 사항은 태그 검수 창과 XLSX의 `태그검수` 시트에서 볼 수 있다. 이전에 저장되지 않은 원래 제안은 빈칸으로 둔다.

고정 베이스·분석/추출·수동 편집·이미지 저장·보안 키·비용 한도 및 공급자 어댑터는 유지한다. 추가 호출과 자동 재시도는 없다. 검수 중점은 API에 전달되므로 설정 안내에 전송 범위를 표시한다. 개인 중점 메모는 공개 저장소나 프로그램 기본값에 넣지 않는다.

106개 Python/HTTP 검사와 17개 Chromium 검사 통과. 제공된 5개 원문과 이전 XLSX를 이용한 합성 응답 재생으로 저장·근거 일치를 확인했다. 이는 실제 모델 재분석이나 의미 정확도 측정이 아니다. 사용자 PC에서 패치를 적용하고 동일 5개를 실제 재분석한 결과를 받아 비교해야 사전준비의 품질 검증을 마칠 수 있다. 새 Windows 네이티브 실행은 별도 확인이 필요하다.
