# 0.3.1:实际 PT 반입 오류와 승인 사례 API 경로 보완

## 사용자가 확인한 실제 실패

사용자 PC의 반입 검토창은 PT를 **495개**로 나눴습니다. 배경 갤러리의 **309/309**는 미리 적재한 승인 자료이며 추출 성공 수치가 아닙니다. 검토창에는 제목만 있는 후보도 별도 카드로 포함됐습니다. 등록은 동일 원문의 승인 카드 복수 후보 중 귀속 대상을 고르지 않아 중단됐습니다. 등록 전에 검증이 실패했으므로 이 스크린샷에서 신규 등록 성공을 주장하지 않습니다.

실제 XML을 아직 받지 못했으므로 제목 앞뒤 공백·페이지 나눔·표 행 중 어느 신호가 잘못 작동했는지 확정하지 못했습니다. **이번 진단판은 495→309 분리 문제를 해결했다고 주장하는 버전이 아닙니다.** 목표 개수나 승인 원문 조회로 강제 병합하지 않았습니다.

## 이번에 보완한 것

- 검토창에서 이번 추출 수와 기존 갤러리/승인 카드 수를 구분합니다.
- 등록 전에 누락된 귀속 선택을 검사하고 해당 카드로 이동·포커스합니다. 서버 오류도 정확한 검토 카드 번호와 승인 후보를 반환합니다.
- 같은 신규 원문에 한해 사용자의 명시적 귀속 선택을 공유합니다. 서로 다른 원문에는 복사하지 않습니다. 저장된 선택은 다음 반입에 표시합니다.
- 같은 HWPX를 파일 선택창에서 다시 골라도 반입 이벤트가 발생하도록 수정했습니다.
- **구조 진단 ZIP 저장**: 반입 검토창에서 등록 없이 원본 XML·HPF 및 문단/카드/이미지참조 정보를 새 ZIP으로 저장합니다. BinData·미리보기·썸네일 파일 바이트는 제외합니다. 원문은 XML에 포함되며, 자동 전송하지 않습니다. 원본 파일 SHA와 복사한 XML SHA를 보존합니다.
- 선택적으로 사용할 수 있는 오프라인 PowerShell 수집 스크립트도 소스에 포함했습니다. 이 스크립트의 Windows 실행은 미검증이며 앱 안의 진단 내보내기를 우선 사용합니다.
- API의 **관련 승인 카드 사례 참조** 경로를 추가했습니다. 사용자가 API 설정에서 이 항목을 켜면 로컬 승인 309카드 중 관련 원문·태그·실제 근거 사례를 소수만 검색해 제공합니다. 갤러리 적재와 API 사례 참조는 별개이며 반입 분리 로직에서는 이 자료를 읽지 않습니다. 기존 표준 태그 및 승인 교정·통합 이력과 함께 신규 원문의 의미 판단을 보조합니다. 관련 사례가 신규 카드의 강제 정답은 아닙니다.

## 사용 순서

1. 기존 프로그램의 **앱 종료** 버튼으로 종료합니다.
2. 새 ZIP은 이전 폴더 위에 덮어쓰지 말고 다른 짧은 경로에 전체 압축 해제합니다. 같은 사용자 데이터 위치를 사용하며 승인 원본은 변경하지 않습니다.
3. 새 EXE에서 PT 복사본을 반입하고 **등록하지 않은 채 구조 진단 ZIP 저장**을 누릅니다.
4. 내려받은 `.diagnostic.zip`을 채팅에 첨부합니다. 실제 이미지가 빠져 있어 원본 605MB 전체보다 작습니다. 이 ZIP은 반입 자료가 아니므로 프로그램에 다시 등록하지 마세요.

## 검증 구분

진단 ZIP의 원본/DB 불변·이미지 제외·XML 바이트 동일성, 정확한 오류 카드 위치, 선택 동기화 및 실제 브라우저 동작은 별도 시험합니다. API 사례 조회와 요청 계약은 모의 공급자 시험으로 검증하며 실제 의미 품질 시험과 구분합니다.

실제 PT의 309/531 재추출·개별 귀속·태그 품질은 여전히 미검증입니다. 실제 API 호출과 Windows 네이티브 실행도 여기에서 완료했다고 보고하지 않습니다. 최종 자동시험 로그와 브라우저 JSON, 빌드 검증 기록은 `evaluation/`에 있습니다.
