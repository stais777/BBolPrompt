# UI 인계 반영과 실행 배포 범위

2026-11-05 사용자가 “ui도 보고 반영해주세용”으로 이전의 보관 지시를 변경했다. 원본ZIP은 그대로 보존하고4파일을 읽어 명세와 시안을 분석했다. 인계 해시JSON에 목록된3개 파일SHA와ZIP CRC를 검증했다. `evaluation/ui-handoff-analysis.json`에 출처를 기록했다.

v0.8 HTML의 CSS를 `web/ui.css` 앞부분에 그대로 보존하고 실제 앱의 연결용 스타일만 덧붙였다. 시안의 가짜 저장/미연결 API 코드·내장 카드 데이터는 복사하지 않았다. 원본 마스터와 기존 API 판단 방법·출처 체계는 유지한다.

## 반영한 동작

- 좌측 태그/검색, 중앙 카드 갤러리, 우측 인스펙터의3영역. 인스펙터 폭 드래그/방향키 조절 및 저장.
- 반입 전 빈 갤러리. 고정309개 DB기준 행과 실제 등록/반입 출처가 있는 표시 카드를 구분한다. 반입 검토와 등록 확정을 거쳐 표시한다. 원본 재분리는 하지 않는다.
- 바둑판0태그/기본2줄/크게3줄/자세히20개. 더보기에서 전체태그에 접근한다. 태그 원본 개수를 줄이지 않는다.
- Windows Workstation/Vision Blue/Cloud White/Carbon Pro/Illustrated Studio와 기본/블루/민트/바이올렛 강조색. v0.8색상 사용, 기본값 복원.
- 태그 선택과 적용을 분리한 AND교집합. 0.3.9부터 **같은 버튼이 태그 적용↔전체 카드 보기로 전환**한다. 전체 보기에서도 선택 유지, 초기화 시 선택/적용 해제. 숨긴 카드 보기는 별도다. 이전 별도 버튼 구현은 인계서4항의 재클릭 토글을 누락했으며 이번에 바로잡았다.
- 이미지→대분류별 전체 태그→전체 원문. 태그/원문 각각 스크롤. 실제 CP/문자열을 검증한 다중 구간 강조. 잘못된 근거는 오류 안내,0구간은 태그 보존.
- 0~N이미지/카드 내부 휠·전환, contain비율 보존, 상세/맞춤/1:1, 원본 바이트 저장, 원문전체 복사. 이미지 복사는 원본 크기를 유지한 PNG픽셀 클립보드이며 원본파일은 바꾸지 않는다.
- 숨김/숨김해제, 사용자 드래그 정렬과 원본 순서 분리, 우클릭 대표 태그 고정. 모든 값은 별도UI설정으로 저장한다.
- 직접 등록:원문·0~N이미지·선택출처→검토→확정. 신규 운영카드의 원문/이미지 수정 전후 검토·수정이력·이전 원문/태그/이미지 연결 복원. 출처는 보존한다. 원문 변경 시 태그명은 보존하고 기존 근거 좌표는 재확인 대상으로 전환한다.
- 테마·보기·패널너비·필터선택/적용·숨김·정렬·대표태그는 SQLite에 저장한다. 실행 때마다 포트가 바뀌므로 localStorage에만 의존하지 않는다.

## 인수 항목과 남은 범위

| 인계ID | 현재 판정 |
|---|---|
|UI-01~06|브라우저 합성자료로 빈 갤러리·4보기·태그/원문 순서·다중형광펜·선택/적용 AND·전체/초기화를 검증.|
|UI-07~10|브라우저 합성자료로0/N이미지·휠·저장/복사·3비율·1:1·너비·5테마/강조색/모달을 검증. Windows의 클립보드/화면 배율은 별도.|
|UI-11~14|브라우저 합성자료로숨김·정렬·등록검토·신규수정/원문diff/복원 및 저장 계층 보호를 검증.|
|UI-15|동일 원문/이미지 추가의 운영 저장·기존 진단 회귀는 있음. 확정 PT의 재등록은 합성으로검증. 새 HWPX소스 버전 비교/불확실 대응 UI는 미구현.|
|UI-16|승인 카탈로그SHA불변·고정ID/태그/근거 수량 및 출처를 검증. 실제PT원본은 이 환경에 없음.|
|UI-17|Windows/Hancom에 원문+이미지를 원스텝 삽입하는 네이티브DnD는 미구현·미검증. 내부정렬과 복사/저장은 이 기능의 완료 증거가 아니다.|
|UI-18|영상 소스/씬 연계 UI·저장 모델 미구현. 영상 태그를 이미지에 자동 전파하지 않음.|
|UI-19|새 포트로 앱을 재실행한SQLite설정/카드 보존과DB+이미지 백업 검증. 전체bak를 앱에서 복원하는 화면과 주기적시간 백업은 후속. 카드별 수정복원과 구분.|
|UI-20|잘못된파일/이미지없음/근거없음/API비활성/저장검증 실패를 안내. 실제 Windows경로/한컴연동/지원포맷별 전수 시험은 후속.|

실행 증빙:`evaluation/ui-integrated-tests.log`(111개), `ui-handoff-browser.json`, `browser-smoke.json`, `baseline-browser-smoke.json`. 외부API는 호출하지 않았고 실제PT/Windows실행은 수행하지 않았다. UI인계 전체20항목을 Windows에서 합격했다고 보고하지 않는다.

원본UI ZIP의 해시JSON은 `master_present:true`지만 실제ZIP구성4개에는XLSX가 없다. 최종마스터는 별도 인계본과 기존 고정자료에서 확인했다. 첨부의665개와 사용자 실측495개는 각각의 출처로 유지한다.
