# 고정309개 사용자 태그 수정 — 0.3.6-manualtags

사용자 확정 정책: 최초309개 정답 데이터는 영구 보존하고, 사용자가 해당 카드의 태그를 직접 수정해 저장한 경우만 변경을 적용한다. API·재분석·다른 카드 교정·운영 분류 설정은 기준 태그/하이라이팅을 덮어쓰지 않는다.

## 사용 방법

1. 카드 선택 → **태그 수정**을 연다. 원문·이미지 편집과 API분석은 기준 카드에서 계속 차단한다.
2. 태그명·소속·원문 근거를 직접 수정하거나 태그를 추가/삭제하고 **저장**한다. 최초 원본은 그대로 두고 이 카드의 사용자 수정본을 별도로 적용한다. 편집창을 닫는 것만으로 저장하지 않는다.
3. **태그 수정 이력 · 복원**에서 이전 수정본이나 **최초 정답 원본으로 복원**을 선택한다. 복원 후에도 기존 이력을 삭제하지 않으며, 원문·이미지 순서는 유지한다.

태그명만 바꾸면 다중 근거와 기존 Unicode좌표를 그대로 유지한다. 근거를 직접 바꾸면 정확한 원문인지 검사하고, 여러 번 나오는 짧은 구절은 더 긴 인용을 요청한다. 사용자가 근거 없이 확정한 태그는 빈 구간으로 보존한다. 임의 하이라이트를 만들지 않는다.

다른 창에서 먼저 저장했으면 오래된 편집 내용을 거절한다. 다시 불러온 뒤 수정한다. 같은 원문이 있는 다른 카드도 고정ID별로 구분한다. 운영 분류의 표시명 변경·비활성화는 기준 카드의 태그·분류를 자동 변경하지 않는다. 기존 비활성 소속은 수동 태그명 변경 때 유지할 수 있다.

## 원본·수정본·복원

- 해시 고정 원본 카탈로그/매니페스트/마스터와 baseline_cards는 그대로 유지한다. 원본은 버전0으로 언제든 조회·복원한다.
- 사용자 수정은 library.sqlite3의 별도 baseline_tag_editions에 카드ID·순차 버전·시각·작업·원문/원본/수정태그 해시와 함께 추가한다. 변경/삭제 트리거로 과거 이력을 보호한다. 동일 내용 저장은 불필요한 버전을 추가하지 않는다.
- 기존 전체 백업 형식은 이 테이블을 함께 포함한다. 별도 임시 저장소로 복원해 최초 원본과 모든 사용자 수정 버전의 보존을 검증했다. 백업 효율화/공유 저장소 재설계는 이번 범위에 포함하지 않는다.
- 구버전0.3.5 이하는 새 사용자 수정본을 표시하지 못하고 최초 원본만 표시할 수 있다. 사용자 수정 기능을 사용한 뒤에는0.3.6 이상을 사용한다.

## API 참고 범위

기준 카드 자체의 API분석은 계속 차단한다. 신규 카드의 **관련 기준 카드 사례 제공** 옵션을 켠 경우에만 최신 사용자 확정 태그·원문 발췌·근거를 최대3건/기존분량한도 안에서 제공한다. 이력 전체·309개 전체 원문·이미지를 보내지 않는다. 수정된 카드의 예전 승인 사례는 선택 이력에서 제외하고, 선택한 최신 사례에 수정 버전/해시를 붙인다. 새 태그ID도 validator가 인식하도록 연결한다.

한 카드의 수정은 그 카드에 적용한다. 다른 카드의 태그를 자동 교정하거나 전역 규칙으로 승격하지 않는다. 이는 최신 사용자 자료를 요청에 제공하는 기능이며 모델 재학습이나 실제 의미 정확도 검증이 아니다. 일반 신규 카드의 교정 학습 원장·한영 검색 강화 등 별도 개선안 전체를 구현했다는 뜻도 아니다.

## 진단과 검증

진단 ZIP의 기존 tag_mappings/spans는 최초 원본8471/10358을 검사한다. manual_tag_edits에는 수정 카드 수·이력 수·최신 버전/해시/개수·오류만 넣는다. 사용자 태그명·근거 원문은 내보내지 않는다. 사용자 수정으로 화면 태그 수가 달라져도 원본 손상과 구분한다.

통합154개(새 수동 편집14개 포함), 수동 편집 브라우저9개, 기존 화면 회귀16개를 통과했다. 원본309개 편집 왕복, 다중 근거 이름 변경, 삭제/추가/복원, 오래된 창 충돌, 동일원문 ID분리, 자동 분류 변경 차단, 백업 복원, 이력 변조 감지, 최신 사용자 사례의 모의 API참고를 확인했다.

시험은 Linux의 합성 HWPX·임시 SQLite·모의 API다. 새0.3.6의 실제 Windows 수동 수정과 실제 API는 미검증이다. 사용자의 이전0.3.5 실제 Windows 등록 성공과 새 기능의 시험을 구분한다. 실제 키·API요금은 사용하지 않았다.
