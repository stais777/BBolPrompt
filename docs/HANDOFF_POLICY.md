# 변경 기록과 전체 인계 원칙

사용자 확정:업데이트할 때마다 전체 코드나 전체 ZIP을 다시 전달할 필요는 없다.

- 평소:변경 파일, 확정 결정, 근거 출처, 실행한 시험, 남은 문제를 기록한다. 실행 파일이 바뀌지 않았으면 새 배포본이라고 하지 않는다.
- 체크포인트:큰 단계가 끝나거나 채팅을 옮기기 전에 전체 소스·원본 자료·검증 결과·현재 상태·다음 순서를 묶는다.
- 새 대화는 이 대화의 세부사항을 자동으로 기억한다고 가정하지 않는다. `SESSION_STATE.md`와 원본/해시를 함께 전달한다.
- 비밀키, 실제 사용자DB, 캐시·도구체인·임시작업파일은 포함하지 않는다. 실제 존재하지 않는 원본PT나 이미지가 포함됐다고 쓰지 않는다.
- 보관만 요청한 자료는 원본ZIP그대로만 보존하고 실제 분석 상태를 표시한다. UI는2026-11-05 이후 사용자가 분석·적용을 승인했으므로 최신 수신기록과UI_IMPLEMENTATION.md를 따른다.
- 인계본을 만들었다는 사실과 GitHub업로드/실행파일배포를 구분한다. 원본 새자료가 포함된 전체 인계본을 자동으로 외부 게시하지 않는다.
- 도구의 파일크기 제한에 맞춰32MiB이하의 독립 ZIP으로 나눌 수 있다. 단순 바이너리 조각이 아닌 정상 ZIP으로 만들어 새대화에서 각각 압축해제할 수 있게 한다.
