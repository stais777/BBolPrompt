# 0.3.8-startupfix — 이전 앱 실행 감지와 시작 오류 안내

사용자0.3.7 실행 로그는 이전 앱의 health 응답을 감지해 자료 복사를 차단한 기록이다. 사용자는 작업관리자에서 종료한 뒤에도 같은 안내가 나온다고 보고했다. 원본 로그 두 개는 내용이 같고 시각/포트가 없으므로 실제로 어떤 프로세스가 응답했는지, 같은 오류 기록이 남은 것인지는 해당 자료만으로 확정하지 않는다. 원본 로그와 사용자 경로는 공개하지 않는다.

개발 환경에서는 원래 저장한 포트를 **다른 자료 폴더의 뽈프롬**이 사용하면0.3.7이 잘못 차단하는 경우를 재현했다. 이전 검사는 health의 ok/309만 확인했고 자료 폴더나 PID를 확인하지 않았다. 이는 재현된 결함이며 사용자PC의 원인이 동일하다고 확정한 결과는 아니다.

## 결과 동작

- 새 health/runtime 기록에는 자료 폴더의 SHA256 식별값과 PID를 제공한다. 원본 경로·카드·API키·세션 토큰은 health에 제공하지 않는다. 다른 자료 폴더의 앱이 포트를 재사용하면 이사를 막지 않는다.
-0.3.7 이하 health에는 자료 식별값이 없으므로 저장한 PID가 확실히 종료됐는지 추가로 확인한다. PID 상태가 불명확하면 실행 감지를 우회하지 않는다. Windows에서는 SYNCHRONIZE 권한의 프로세스 핸들을 열어 대기 상태만 확인하고 닫는다. os.kill이나 TerminateProcess로 종료하지 않는다.
- 실제 응답하는 이전 앱이 있으면 브라우저에서 그 로컬 화면을 열어 사용자가 **앱 종료**를 누르게 한다. 자동 종료·강제 종료는 없다. 오류창에는 현재 실행의 구체적 안내와 해당 주소를 표시한다.
- 실행할 때 이전 startup-error.log와 오류창용 메시지를 정리한다. 새 실패 로그에는 UTC 시각/버전을 기록한다. 런처도 이전 오류창 메시지를 먼저 지워 과거 메시지를 재사용하지 않는다. 쓰기 실패 시에는 일반 안내로 남고 기존 자료를 삭제하지 않는다.

## 사용

기존 앱 종료 후 새 ZIP 전체를 쓰기 가능한 새 폴더에 푼다. 새 폴더 실행 시 기존 자료를 복사·검증한다. 이미0.3.7의 data를 사용 중이면 data를 함께 옮기거나 기존 폴더의 프로그램 파일을 업데이트하며 data를 보존한다. 이전 앱 화면이 따로 열리면 그 화면의 **앱 종료**를 누르고 새 버전을 다시 실행한다. PT는 앱이 열린 뒤 원본 보관 버튼에서 선택한다.

최초309개 원본/매핑/태그/하이라이팅·사용자 수동 수정 이력·신규 카드·원본보관·호출원장의 의미를 변경하지 않는다. 복사 검증/실행 중 차단/이전 자료 보존은 유지한다. runtime.json이나 data를 지워 우회하는 절차를 제공하지 않는다.

## 시험의 한계

수정 전6개 새 검사에서3실패/3오류로 재현했고 수정 후 Windows 프로세스 API 모형3개를 더한9개 검사를 통과했다. 현재 실행 중 같은 자료는 차단, 다른 자료는 허용, 종료 PID/불명확 PID 처리, 사용자 수정 보존, 이전 화면 열기, 새 메시지/시각, 과거 오류 정리를 임시DB/로컬HTTP로 확인했다. Windows 핸들 검사는 모형이며 실제 Windows API 실행이 아니다. 통합/브라우저/배포 검증의 최종 수치는 해당 평가 영수증에 기록한다. 사용자PC에서 새 버전의 해결 여부는 재실행 확인 전까지 미확정이다.

최종 자동시험은 **188개(새9개 포함)**, 실제 Chromium의 기존 원본보관/수정/이사 화면 검사는 **8개** 통과했다. 시작 시 이전 화면 열기는 모의 webbrowser 호출로 확인했다. 이전 앱 강제종료/자료 삭제/실행 감지 강제 우회는 추가하지 않았다. 보호 자료10개가 변경 전과 같다. `evaluation/startup-recovery-scope.json`, `startup-recovery-integrated-tests.log`, `startup-recovery-portable-browser.log` 참조.
