# 뽈프롬 인계 분석과 검증 근거

작성 기준: 2026-11-04 인계 ZIP. 승인 원본은 `/workspace/bbolprompt-handoff`에 보존했고, 수정 코드는 별도 `Bbolprompt` 디렉터리에 작성했다. 아래 결과는 실제 실행한 평가의 범위를 구분한다. 프로그램 전체 납품/Windows 실행 완료 선언이 아니다.

## 원본 및 승인 데이터 보호

`evaluation/audit_handoff.py`는 manifest의 120개 항목에 대해 크기와 SHA-256을 대조한다. 최초 실행에서 120/120 일치했다. 최종 XLSX의 SHA-256은 `b59c80d08222f33e8d2e23964e88ec2432153c3a12db48a14c788dc730284fbe`로 지정값과 일치한다.

XLSX `카드별태그`의 실제 309행, C~I 태그 매핑 8,471건이 평가용 baseline의 카드별 태그 집합과 일치한다. 최종 HTML에 내장된 원문과 태그 집합도 동일하다. baseline에서 2,200개 고유 태그명, 10,358개 근거 구간을 확인했다. 모든 구간에서 `text[start_cp:end_cp] == evidence`를 확인했다. 승인 태그 중 **17건은 근거 구간이 0개**이므로 새 엔진에서 이런 태그를 임의로 제거하거나 구간을 꾸며서는 안 된다.

`assets/approved_catalog.json`은 기존 승인 카드를 읽기 전용 갤러리에 표시하기 위한 사본이며, 분리/추론/API 조회 정답 입력이 아니다. 원본 master 및 baseline의 출처 SHA를 포함한다. 최종 HTML에는 실제 이미지 바이트가 없어서 기존 이미지 참조만 보존한다. 표시할 이미지가 없음을 실제 이미지 생성으로 대신하지 않는다.

승인 309카드의 원문 SHA는 296개로, 서로 다른 승인 카드가 같은 원문을 갖는 12개 묶음(총 13개 추가 카드)이 존재한다. 이 승인 구조를 자동 병합하지 않는다. 같은 승인 원문을 새로 반입할 때 이미지·출처는 사용자 데이터 오버레이로 추가하고, 원문이 같은 승인 카드가 여럿이면 귀속 카드 ID를 사용자가 명시적으로 선택해야 한다. 선택 이후 같은 원문은 그 결정을 재사용한다. 이 경로도 실제 HTTP 테스트로 검증했다.

## 실측 실패 자료가 말하는 것

두 JSON은 동일한 실제 PT SHA-256 `c5d52ce0cda5901d9da178f88c8d5c2eeb5614eefa5a0546916e4951df881ddf`를 가리킨다. A/B는 API 사용 여부가 아니라 각각 기존 generic, approved_terms 모드다. 둘 다 로컬 규칙 엔진이다.

| 지표 | A generic | B approved_terms |
|---|---:|---:|
| 추출 카드 / 승인 카드 | 1,156 / 309 | 1,156 / 309 |
| 원문 완전 일치 / 부분 / 미매칭 | 218 / 18 / 73 | 218 / 18 / 73 |
| 엔진 미매칭 카드 | 920 | 920 |
| 올바른 이미지 귀속 / 기준 | 425 / 531 | 425 / 531 |
| 태그 일치 / 생성 / 기준 | 421 / 4,288 / 8,471 | 1,719 / 7,063 / 8,471 |
| 태그 recall / precision | 4.97% / 9.82% | 20.29% / 24.34% |
| 일치 하이라이팅 / 전체 기준 | 236 / 10,358 | 1,460 / 10,358 |

카드별 자료를 다시 합산한 태그 false negative는 A 8,050건, B 6,752건이다. 정렬된 카드 내 false positive는 A 1,884건, B 2,675건이다. 이 수치는 미매칭 엔진 카드에서 생성된 태그를 포함하지 않으므로 전체 생성 태그에서 정답 수를 뺀 값과 다르다. 이미지 누락/잘못 귀속은 106건이다. 카드별 원문 관계/누락/과잉은 `evaluation/historical-card-failures.csv`에 보존했다.

원문 경계가 이미 실패한 전체 recall을 독립적인 AI 의미 판정 정확도로 해석할 수 없다. 좌표 비교는 원문이 동일한 경우만 의미가 있다.

## 소스 수준 결함과 평가로 확인한 수정

이전 `analysis.split_cards`의 paragraph/auto는 각 텍스트 문단을 카드로 만들어 여러 문단으로 된 한 카드가 분해됐다. 이전 `hwpx.read_paragraphs`는 모든 `p`를 순회하면서 상위 `p` 안의 하위 `p`도 재귀 수집하여 테이블 안의 텍스트/이미지가 중복 집계될 수 있었다. 새 구조 기반 분리는 이미지 블록, 테이블 행, 단락/페이지/섹션 경계 정보를 사용한다. 정답 309 문자열 조회로 경계를 맞추지 않는다. 구조적으로 모호한 문서는 경고를 보존한다.

`evaluation/structural_regression.py`는 승인 원문과 무관한 새 HWPX 두 개를 직접 생성한 후 이전 코드와 새 코드를 별도 Python 프로세스에서 실행했다.

| 직접 만든 회귀 사례 | 이전 Alpha | 수정본 |
|---|---|---|
| 두 카드, 각 2개 원문 문단 + 뒤쪽 복수 이미지 | 4카드, 원문/이미지 완전 일치 0/2 | 2카드, 완전 일치 2/2 |
| 중첩 테이블의 두 행, 행마다 원문/이미지 | 3카드, 이미지 참조 4 | 2카드, 이미지 참조 2, 완전 일치 2/2 |

이 결과는 해당 결함 재현 및 수정 근거다. **실제 PT에서 309카드/531개 이미지 귀속을 달성했다는 의미가 아니다.**

제공된 `_v07_small_simulated.hwpx`도 양쪽 엔진에서 실행했다. XML에는 원문 문단 309개, 이미지 참조 0개, ZIP에는 쓰이지 않는 BMP 1개뿐이었다. 양쪽 모두 309카드/0참조를 반환했다. 이 파일을 실제 PT의 다문단·복수 이미지 시험으로 취급할 수 없다.

원본 Alpha 테스트는 원래 디렉터리에서 다시 실행해 6개 모두 통과했다(`evaluation/original-tests.log`). 기존 시험들이 실제 경계 결함을 검출하지 못했다는 점도 확인된다.

## 승인 이력의 의미

최종 XLSX에는 106개 시트가 있다. 단순 2,200개 라벨 이외에 `B_001-309_최종승인사전`, `가로1차_승인변경이력`, `가로_다음차수적용기준`, `가로2차_승인변경이력`, `가로2차_다음차수적용기준` 등 실제 사용자 승인 이력이 존재한다. 승인 사례 조회에는 이 출처 및 행 번호를 보존해야 한다. 예시로 만든 정규화 원칙을 실제 승인 사실로 꾸미지 않는다. API 어댑터 mock 시험은 구조/오류 처리 검증이며 실제 API 의미 정확도 검증과 구분한다.

## 아직 확인할 수 없는 항목

605MB 실제 `PT.hwpx`는 첨부 ZIP에 없다. 과거 comparison JSON에는 완전한 HWPX XML 구조나 실제 이미지 바이트가 없으므로 원래 입력을 복원할 수 없다. 현재 실제 PT 개선 수치, 531개 참조의 개별 귀속, 실제 이미지 바이너리 무결성 전체를 재측정하지 않았다.

실제 API 호출의 품질/비용/실패는 실제 연결 설정과 호출 없이 검증했다고 할 수 없다. 모의 응답이 정확한 태그를 내는 시험은 API가 그 태그를 스스로 판단한다는 증거가 아니다. Windows 실행 파일은 빌드 산출물 존재, PE 형식 확인, 실제 Windows 독립 실행 시험을 구분해야 한다. 빌드 스크립트만 존재하면 실행 파일 납품 완료로 볼 수 없다.

## 재현 명령

개발 디렉터리에서:

```bash
python evaluation/audit_handoff.py --handoff /path/to/extracted/handoff
python evaluation/structural_regression.py --handoff /path/to/extracted/handoff
python -m unittest discover -s tests -v
```

평가 모듈과 승인 baseline은 운영 추론에서 import하지 않는다. 최종 산출 시 manifest 검증을 다시 실행해 원본 불변을 확인한다.

## 이번 수정본의 최종 회귀 실행

전체 `unittest` 69개를 실제 실행해 모두 통과했다. 그중 사용자 SQLite/해시/백업/XLSX 시험 9개, 실제 localhost HTTP 시험 15개를 포함한다. HTTP 시험에서는 원문 동일 승인카드의 이미지/출처 오버레이, 중복 원문 승인카드의 명시적 귀속, 사용자 태그의 코드포인트 다중 근거와 빈 근거 보존, 잘못된 편집의 무변경 거부, 승인카드 편집 차단도 검증했다. 원격 API 오류 시험은 전송만 모의 처리했으며 실제 API 의미 품질 시험은 아니다. 명령 출력은 `evaluation/final-integrated-tests.log`, 범위는 `evaluation/app-library-functional.json`에 기록했다.

원문 구조 진단 내보내기도 추가 검증했다. 3개의 직접 진단 시험과 HTTP 시험에서 원본 XML/HPF 및 출처 SHA·카드/문단 특징 보존, BinData·미리보기·썸네일 이미지 바이트 제외, 진단 생성 시 DB·원본 무변경, 업로드 취소 이후에도 진단 ZIP 다운로드 가능을 확인했다. 이는 실제 PT의 잘못된 경계를 분석할 입력 수집 경로이며, PT 분리 성능을 수정하거나 검증한 결과가 아니다. 동일 원문 승인카드의 귀속 오류는 정확한 검토 카드 번호와 선택지를 구조화해 반환하는 것도 확인했다.

## 후속 0.3.1 검증

사용자가 실제 PT 반입 검토495개를 보고했고 초기 갤러리309개와 구분됩니다. 구조 분리 결함은 미해결로 기록했습니다. API의 관련 승인 원문·태그·근거 참조, 진단 ZIP과 오류 위치 안내를 보완한 최종 시험은 자동80/80·Chromium16/16이며 `final-integrated-tests.log`, `browser-smoke.json`, `windows-build-0.3.1-diagnostic.json`에 기록했습니다. 실제 API 의미 품질·실제 PT 개선 측정은 여전히 미실행입니다.
