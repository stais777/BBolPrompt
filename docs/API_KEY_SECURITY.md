# API 키 보안 준비 (0.3.4-security)

사용자 요청: 개인 키 유출과 불필요한 과금을 줄인다. 결제 제한은 사용자도 공급자에서 설정할 예정이다. 이번 변경은 보안 경계에만 적용한다. 고정309카드·원본 마스터·이미지 매핑·태그/하이라이팅 판단 방법은 변경하지 않았다. 실제 베이스파일 검증·사용자 확정 전 후속 엔진 개선은 계속 보류한다.

## 키 보관과 전송

- 키는 Windows 자격 증명 관리자의 고정 대상 `Bbolprom/OpenAI/APIKey/v1`에 일반 자격 증명으로 저장한다. 현재 Windows 사용자의 로컬 컴퓨터에 보관하며 로밍하지 않는다 (`CRED_PERSIST_LOCAL_MACHINE`). 별도 암호화 알고리즘을 만들지 않는다.
- 설정창의 비밀번호 입력칸 → 세션 토큰으로 인증한 루프백 HTTP → Win32 `CredWriteW`. `CredReadW`/`CredFree`로 읽고 `CredDeleteW`로 로컬 보관값을 삭제한다. 입력칸은 전송 직전과 성공/실패/닫기 때 비운다. 키를 브라우저 저장소나 앱 설정에 기록하지 않는다.
- 브라우저에는 키 존재 여부와 보관함 사용 가능 여부만 반환한다. 일반 설정·SQLite 라이브러리·진단 ZIP·내보내기·백업에는 키를 넣지 않는다. EXE나 Git에도 키를 내장하지 않는다. 키 요청은 2KB로 제한하고 입력·OS 오류 원문은 반사하지 않는다.
- 환경변수·평문 파일로 대체 저장/읽기하지 않는다. Windows 보관함이 없거나 읽기에 실패하면 호출을 중단한다. 기존 `BBOLPROM_API_KEY` 환경변수는 자동 이전하거나 읽지 않는다. 사용자가 필요하면 전용 입력칸으로 직접 등록한다.
- 목적지는 정확히 `https://api.openai.com/v1/chat/completions`만 허용한다. 다른 호스트·경로·포트·URL 사용자정보·쿼리·조각·비슷한 악성 호스트를 거절한다. 키는 TLS로 보호되는 Authorization 헤더에만 넣고 요청 본문·URL에는 넣지 않는다. 기본 인증서·호스트 검증, 상속된 네트워크 프록시를 유지하며 모든 리다이렉트를 거절한다.
- 로컬 서버는 `127.0.0.1`에만 연다. 키 변경을 포함한 POST는 세션 토큰·Host·Origin을 검사한다. HTML을 포함한 GET에도 Host를 검사한다. 접근 로그를 쓰지 않는다. API 오류는 응답 본문·인증 헤더·키를 노출하지 않는다.

## 호출과 비용 보호

- 기본 API 꺼짐, 외부 전송 동의 필요. 활성 사용자 분류 정의가 없으면 유료 호출을 하지 않는다. 선택 모델은 사용자가 정한 `gpt-6.1-sol`이며 이 계정의 접근 권한·실 호출은 확인하지 않았다.
- 하루 최대 호출 수와 예상 비용 상한은 UTC 일자 기준이다. 비용 상한 및 현재 모델의 입력·출력 단가를 양수로 입력하기 전에는 호출하지 않는다. 단가는 프로그램이 자동 확인하지 않으며 실제 청구액 보장은 아니다.
- 요청 UTF-8 바이트 수와 최대 출력 토큰으로 비용을 예약한다. 별도 `api-safety.sqlite3`에 SQLite `BEGIN IMMEDIATE`로 호출 전에 예약을 확정한다. 동시 실행도 같은 사용 원장을 확인한다. 기록 실패 시 호출하지 않는다. 사용 원장에는 키·원문·응답을 저장하지 않는다.
- 재실행·API 설정 저장은 사용 원장을 초기화하지 않는다. 라이브러리 백업에는 원장을 넣지 않으므로 과거 라이브러리 복원으로 오늘 사용량을 되돌리지 않는다. 실패·타임아웃·중단의 예약은 유지하고 자동 재시도하지 않는다. 정상 응답에 사용량이 있으면 지정한 단가로 조정한다.
- 이 한도는 이 데이터 폴더의 앱 호출에 대한 로컬 보호다. 다른 프로그램·다른 데이터 폴더·유출된 키 사용·고의로 사용 원장을 삭제하는 행위나 단가 오류까지 통제하지 않는다. 공급자의 계정 결제 설정은 별도로 필요하다. 알림 예산과 실제 차단 한도는 공급자 화면에서 구분해야 한다.

## 보호의 한계와 검증 범위

Windows 보관함은 평문 파일 저장을 줄이는 보호다. 같은 사용자 권한의 악성코드·관리자·키보드 입력 감시·브라우저 확장·프로세스 메모리를 완전히 막지 못한다. Python 문자열과 브라우저 메모리의 키를 완전히 지웠다고 보장하지 않는다. 개발자 키를 사용자에게 내장 배포하지 않는다. 유출 의심 시 로컬 삭제만으로 해결하지 말고 공급자에서 키를 폐기·재발급해야 한다.

`tests/test_api_security.py`는 합성 키로 Win32 호출 모의시험, 주소 차단, TLS/리다이렉트 설정, 키 없는 저장/백업/진단, 인증·Origin·Host 차단, 동시 호출, 재실행·설정 변경, 오류 후 예약 유지와 기록 실패 차단을 시험한다. `scripts/api_security_browser_smoke.js`는 실제 로컬 UI와 메모리 보관함으로 입력 마스킹·비우기·교체·삭제·오류를 시험한다.

실제 API·실제 키·실제 PT 파일을 사용하지 않았다. Linux에서 Win32 함수 호출을 모의했으며 실제 Windows 자격 증명 관리자와 Windows EXE 실행 검증은 남아 있다. 모의시험을 Windows 보안 실측이나 실제 모델 품질로 보고하지 않는다.
