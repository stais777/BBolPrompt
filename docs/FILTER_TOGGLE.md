# 0.3.9 — 태그 필터를 같은 버튼으로 전환

UI인계의 최신 확정사항4항은 `태그 적용/전체 보기 간에 빠르게 왕복할 수 있도록 같은 위치에서 재클릭 토글하는 동작`을 포함한다. 사용자가0.3.8 화면의 별도 버튼 배치를 지적했고 이 누락을 바로잡았다. 원본 인계파일은 변경하지 않았다.

태그 선택 후 **태그 적용** → AND 결과와 함께 같은 버튼이 **전체 카드 보기**로 바뀜 → 그 버튼을 누르면 전체 보기로 돌아가고 **태그 적용**으로 바뀜. 선택 태그는 보존하며 다시 적용할 수 있다. **태그 초기화**는 선택/적용을 모두 해제하는 별도 버튼이다. 숨김 카드 보기와 분리한다. 여기서 전체 보기는 필터를 해제한 카드 보기이며 OS/브라우저 전체화면 기능이 아니다.

선택 태그와 적용된 태그 스냅샷은 계속 분리한다. 적용 중 선택을 변경해도 결과를 즉시 바꾸지 않으며, 전체 보기로 돌아가 새 선택을 다시 적용한다. 기존 UI설정을 그대로 사용하고 DB 형식을 바꾸지 않는다. 버튼 폭을 유지해 제목이 바뀌어도 같은 위치에서 누를 수 있다. 기본 button의 키보드 동작과 aria-pressed 상태를 유지한다.

변경 범위는 웹 화면3파일과 버전/배포 안내다. 원본309/카탈로그/태그/하이라이팅·API 판단·수동 수정 이력·문서 보관·저장·보안 모듈은 동일하다.0.3.8의 사용자 정상 진입 보고와0.3.9 UI의 사용자 검증은 구분한다.

기존 브라우저 검사에서 별도 전체보기 버튼이 남은 것을 확인해 수정 전 실패했다. 수정 후16개 회귀가 통과했다. AND 결과 수·동일 위치/폭·선택 보존·새로고침 후 상태·Enter 재적용·초기화·원문/이미지·수동 편집·다운로드를 합성자료/임시DB로 검증했다. 외부 요청/API호출 없음. 엔진/저장 등15파일 해시 불변. 백엔드 Python 통합 검사는 이번에 재실행하지 않았다.188개는 이전0.3.8 결과다. 실제Windows0.3.9 UI는 별도 사용자 확인이 필요하다.

**업데이트:**0.3.8에서는 앱 내부 [앱 종료] 후 작은 패치 ZIP 안의 모든 파일/폴더를 현재 Bbolprom.exe가 있는 폴더에 덮어쓰고 다시 실행한다. data는 포함하지 않는다.0.3.8 원본 번들에 패치를 적용한 뒤 새 전체번들과의 모든 파일 해시 일치를 확인한 패치만 전달한다. 다른 버전/파일 변경 이력이 불명확하면 전체 Windows ZIP을 사용하며 data를 보존한다.
