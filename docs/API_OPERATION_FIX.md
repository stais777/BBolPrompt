# 등록·API 분석 응답 보완 — 0.4.2-operations

신규 카드 등록 후 진행 상태를 찾기 어렵고, API 분석 대기 중 숨김 저장까지 지연되는 문제를 수정했다. 사용자 PC에서 발생했던 실제 공급자 실패의 원인은 아직 확정하지 않았다.

## 변경

- 등록 확정 후 진행·경과 시간을 검토창 안에 표시한다. 처리 중 등록·뒤로·취소·Escape를 막고, 실제 저장과 목록 갱신을 구분한다. 저장 후 표시만 실패하면 ‘등록 결과 다시 표시’는 목록만 읽는다. 응답을 잃었을 때 기존 동일 원문 카드가 있다는 사실만으로 등록 성공이라고 표시하지 않는다.
- 유료 공급자 응답을 기다리는 동안 애플리케이션 전체 쓰기 잠금을 잡지 않는다. 별도 분석 잠금으로 진행 중 중복 요청을 공급자 호출 전에 차단한다. 다른 로컬 작업을 허용하고, 대기 중 수동 수정은 기존 리비전 검사로 보호한다.
- 분석 진행·경과 시간·종료 경고를 카드 옆에 표시한다. 선택 카드가 바뀌어도 분석 대상을 유지한다. 카드 선택만으로 갤러리 전체 이미지 요소를 다시 생성하지 않는다. 원본 이미지 바이트·품질은 유지한다.
- ‘분석 상태 확인’은 인증된 로컬 GET이며 모델 호출/자동 재시도를 하지 않는다. 실행 중 상태와 최근 카드별 처리 기록을 읽는다. 기록이 없는 과거 호출의 상세 실패 이유를 복원하지는 못한다.
- 공급자 출력 한도·거절·타임아웃을 구분한다. 내부 APIUnavailable이 ValueError 처리에서 일반 오류로 덮이는 문제를 고쳤다. 위 실패는 기존 태그를 유지하며 자동 재시도하지 않는다.
- 진단에는 허용된 상태·종료 이유·HTTP 코드·입출력/추론 토큰 수만 추가한다. 원문·태그·응답 본문·거절문·키·헤더는 포함하지 않는다. 새 메타데이터가 없는 과거 기록도 안전하게 읽으며 일일 호출/사용량은 기존 로컬 원장에서 읽는다.

‘카드 숨기기’는 원본을 보존하는 숨김/복구 기능이다. 영구 삭제 기능은 이번 범위에 없다. 토큰 사용량을 줄이는 요청 구성 변경도 하지 않았다.

## 보존과 검증

`evaluation/api-operation-preservation.json`: 기준/카탈로그·베이스화·보관·수동수정·보안·예산·API 저장/정의 10파일 SHA 동일. API 판단·근거·스키마·기존 설정 필드/검증과 전송 본문·endpoint·인증/TLS·예산 예약 부분의 AST 동일. 사용자 data를 제공받거나 변경하지 않았다.

- 수정 전 잠금 재현: `evaluation/api-operation-before-tests.log`.
- Python 통합231개: `evaluation/api-operation-integrated-tests.log`. 새 동시성4개·안전 메타데이터4개 포함.
- 새 화면9개: `scripts/api_operation_browser_smoke.js`, `evaluation/api-operation-browser.json`.
- 기존 Chromium45개: API8·갤러리16·베이스수동태그9·보안6·정의설정6. 로그 `evaluation/api-operation-*-browser.log`.

모두 합성 자료·임시 DB·모의 응답으로 실행했다. 실제 키·유료 API 요청은 사용하지 않았다. 실제 계정/모델의 정상 결과·의미 품질·청구 원인과 새 Windows 실행은 확인 전이다. 과거 실패가 해결됐다고 단정하지 않는다.

## 적용 후 확인

앱 안에서 ‘앱 종료’ → 패치 내용 전체를 Bbolprom.exe 폴더에 덮어쓰기 → 재실행한다. 먼저 문제 카드의 ‘분석 상태 확인’을 누르고 새 ‘진단 로그 내보내기’를 제공하면 기존 처리 상태와 사용량을 확인할 수 있다. 확인 전 유료 분석을 다시 누를 필요는 없다. 기존 카드·PT·이미지·키는 재등록하지 않는다.
