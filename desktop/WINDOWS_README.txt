뽈프롬 PromptManager 0.4.4-quality (Windows10/11 x64 시험판)

0.4.4 신규 카드 API 판단 보완
기존 309개 원문·태그·분류·근거와 이미지 연결을 유지합니다.
기존 표준 ID·이름·분류를 함께 재사용하고 승인된 동의어를 통일합니다.
negative: 로 시작하는 줄부터 다음 positive: 제목 또는 원문 끝까지는 태그 대상에서 제외합니다.
일반 본문의 부정문·과거/현재·준비/실제 수행은 문맥별로 구분합니다.
API 설정의 사용자 검수 중점(선택)에 누락 없이 확인할 항목을 입력하고 저장하면 API에 함께 전달합니다.
검수 중점은 원문에 실제 있는 특징의 누락 점검에만 사용하며 빈칸으로 지울 수 있습니다.
XLSX 태그검수 시트에 API 원래 제안·사유·기존 표준·보정 사항을 추가했습니다.
이전 5개 카드에 각각 API 분석을 한 번씩 실행한 뒤 수동 수정 전 XLSX를 내보내 비교합니다.
영상 그룹·영상 엔진·영상 탭은 이번 패치에 구현하지 않았습니다.

0.4.3 저장된 태그 검수
- 신규 카드의 태그를 누르면 원문 강조와 함께 판단/미분류 사유·검증된 원문 근거·같은 이름의 현재 기준 태그를 표시합니다.
- partial은 분석 완료 후 미분류 후보가 남은 상태임을 설명합니다. 기존 저장 결과를 읽으며 추가 API 분석은 필요 없습니다.
- 기준 태그 후보를 표시해도 분류를 자동 변경하지 않습니다. [태그 수정 열기]로 기존 수동 수정 화면을 열 수 있습니다.
- 원본309/태그 판정/요청/키/호출 한도는 유지합니다. 새 Windows 실행은 사용자 PC에서 확인해야 합니다.

0.4.2 등록·분석 응답 보완
- 등록 중 진행 상태를 검토창에 표시하고 중복 등록/취소를 막습니다. 저장 후 목록 표시가 실패하면 [등록 결과 다시 표시]로 목록만 갱신합니다.
- API 분석 중 경과 시간을 카드 옆에 표시합니다. 대기 중에도 카드 숨기기·수동 수정이 가능하며 중복 분석을 차단합니다.
- [분석 상태 확인]은 기존 로컬 기록만 읽습니다. 추가 모델 호출·과금 요청을 하지 않습니다.
- 실패 이유와 토큰 사용 수 같은 제한된 메타데이터를 진단에 포함합니다. 응답 원문·키·요청 헤더는 포함하지 않습니다. 이전 호출에는 새 메타데이터가 없을 수 있습니다.
- [카드 숨기기]는 복구 가능한 숨김입니다. 영구 삭제 기능은 없습니다.
- 실제 계정의 이전 실패 원인과 새 Windows 실행은 아직 확인 전입니다. 업데이트 후 먼저 [분석 상태 확인]과 새 진단 로그로 확인하세요.

0.4.1 설정창 표시 보완: 정의 초안 열기/확정의 진행 및 실패를 설정창 안에 표시합니다.
처리 중 중복 클릭을 막고 실패하면 기존 편집 내용과 재시도 가능 상태를 유지합니다.
이 보완은 실제 사용자PC의 초기화 실패 원인이 해결됐다는 뜻은 아닙니다. 표시된 오류로 원인을 확인하세요.

시작
1. 이전 프로그램에서 [앱 종료] 후 ZIP 전체를 쓰기 가능한 짧은 폴더(예:C:\Bbolprom)에 풉니다.
2. Bbolprom.exe와 app/runtime 폴더를 함께 유지합니다. Python 설치는 필요 없습니다.
3. 처음에는 자료 준비 화면이 열립니다. 이전 사용 자료가 있으면 카드·수정 이력·원본·호출 기록을 data로 복사하고 검증합니다. 기존 폴더는 그대로 남깁니다. 완료될 때까지 기다리세요.
4. 새 사용자: PT.hwpx 선택→검토→[검토한 이미지 연결 등록]. PT 전체 원본은 data\sources\PT.hwpx로 복사하며 기존309개 매핑을 적용합니다. 태그/하이라이팅을 재생성하지 않습니다.
5. 이전 사용자: 복사된 카드·수정 이력·이미지는 그대로 유지합니다. [PT.hwpx 원본 보관]으로 원본 문서를 한 번 선택하면 등록·재분석 없이 문서만 보관합니다.

자료
- data\library.sqlite3: 최초309개, 사용자 태그 수정 이력, 신규카드, 연결, 설정.
- data\sources\PT.hwpx: 베이스파일 전체 원본.
- data\vault: 기존 검증 원본 이미지.
- data\new_cards\카드ID: 버전별 원문.txt와 확장자를 유지한 원본이미지.
- data\api-safety.sqlite3: 일일 API호출/비용 예약 기록.
- 원본 이미지는 축소/재인코딩하지 않습니다. 카드 선택→이미지 클릭→원본크기(1:1)로 확인합니다.
- 사용자 태그 수정은 별도 버전으로 적용하고 최초 정답은 유지합니다. [태그 수정 이력 · 복원]으로 되돌릴 수 있습니다.

새PC/업데이트
- 앱 종료 후 뽈프롬 폴더 전체를 복사하세요. data가 함께 있어야 사용자 수정·신규카드·이미지가 유지됩니다.
- 원래 한글파일 위치나 사용자명/드라이브가 바뀌어도 data 상대경로로 읽습니다.
- API키는 PC의 Windows 보관함에 있으므로 새PC에서 다시 등록합니다. 키를 내장하거나 일반 파일에 복사하지 않습니다.
- 업데이트는 data를 유지하고 프로그램 파일만 교체합니다. 새 폴더로 옮길 때도 data를 함께 가져오세요.
- 현재PC의 작은 최근 자료 위치 기록으로 최신 휴대형 폴더를 찾습니다. 이 기록이 없어도 data가 들어 있는 폴더 자체는 동작합니다.
- 전체 [백업 저장]은 PT·DB·원본이미지를 포함합니다. 자동 수정 백업에는 큰 PT를 반복 포함하지 않습니다. 전체 이사는 폴더 복사를 권하며 전체백업 가져오기 UI는 아직 없습니다.

진단/범위
- [진단 로그 내보내기]로 원본309,531연결,522이미지,수동 이력,보관한 PT/신규 원본 파일의 해시를 확인합니다.
- 진단 ZIP에는 실제 원문/이미지/문서XML/DB/API키/원본 파일명/절대경로가 없습니다. 자동 업로드하지 않습니다.
- 합성자료·임시DB·Linux 로컬 브라우저/프로세스로 시험했습니다. Windows용으로 교차 빌드했으며 새 버전의 실제 Windows 이사·605MB파일 실행·실제 API는 아직 미검증입니다. 자세한 통과 개수/한계는 배포 README를 참조하세요.
- 최초309개의 기준·이미지 매핑과 수동 태그 수정 예외는 유지합니다. 다른 후속 API엔진 개선은 별도 범위입니다.

0.3.8 시작 오류 보완
- 이전 앱의 포트를 다른 자료 폴더 앱이 쓰는 경우를 구분합니다.
- 실제로 응답하는 이전 앱이 있으면 해당 브라우저 화면을 열고 오류창에 주소와 조치 방법을 표시합니다. 그 화면의 [앱 종료] 후 새 버전을 다시 실행하세요.
- 프로세스를 강제 종료하거나 runtime.json/data를 삭제하지 않습니다. 실행 중 자료의 자동 복사는 계속 차단합니다.
- 오류 로그에 실행 시각과 버전을 기록하고 다음 시작 시 이전 오류 기록을 정리합니다.

0.3.9 태그 필터 버튼
- [태그 적용]을 누르면 선택 태그의 AND 결과를 표시하고 같은 버튼이 [전체 카드 보기]로 바뀝니다.
- 같은 버튼으로 전체 보기로 돌아가도 선택은 유지합니다. 다시 [태그 적용]으로 재적용할 수 있습니다.
- [태그 초기화]만 선택/적용을 모두 지웁니다. 단일 버튼은 같은 위치와 폭을 유지합니다.
-0.3.8 사용자는 작은 UI패치의 모든 파일을 Bbolprom.exe가 있는 폴더에 덮어쓸 수 있습니다. 먼저 앱 안의 [앱 종료]를 누르고, 업데이트 후 재실행하세요. data는 패치에 포함하지 않습니다.

0.4.0 신규 카드 API 엔진
- [API · 대분류 설정] → [정의 초안 · 교정 이력 열기]에서 초안을 검토/수정하고 [화면의 정의 확정]을 누릅니다. 기존 사용자 정의가 있으면 그대로 사용할 수 있습니다.
- API키는 Windows 보관함에만 저장합니다. 실제 사용 전 모델명/계정 접근과 현재 단가·일일 한도·전송 동의를 확인하세요. 이번 개발에서 실제 API를 호출하지 않았습니다.
- 신규 카드 선택 → [이 카드 API 분석]. 검증된 결과만 적용하고 수동 태그·제외 이력은 보호합니다. 반복 근거가 애매하면 위치를 임의로 색칠하지 않습니다.
- 관련 사용자 교정의 외부 참고는 별도 옵션이며 기본 꺼짐입니다. [정의 초안 · 교정 이력 열기]에서 다음 추천 참고를 해제할 수 있습니다. 모델 재학습이 아닙니다.
- 신규 카드 [API · 태그 이력]에서 같은 원문 버전의 태그를 복원합니다. 태그만 변경할 때 큰 이미지/문서를 매번 압축하지 않고 이력을 저장합니다. 전체 백업은 기존 기능으로 별도 수행합니다.
- API기록 테이블은 필요한 때 추가하며 최초에는 backup/*.db-snapshot에 DB만 복사합니다. 이 파일은 원본 이미지가 없는 DB 전용 스냅샷이며 전체 원본 백업이 아닙니다.
- 신규 모듈/원본309은 분리합니다. 기존자료 재등록·이사 없이0.3.8 또는0.3.9 폴더에 작은 업데이트를 덮어쓸 수 있습니다. 먼저 앱 안의 [앱 종료]를 누르고 data는 보존하세요.
- 실제 Windows의 새 API엔진·계정 모델 호환·실제 추천 품질은 아직 미검증입니다. 모의 공급자와 개발 환경 검사 결과는 배포 안내에 기록합니다.
